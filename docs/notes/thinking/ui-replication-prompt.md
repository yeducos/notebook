# UI 复刻提示词

将以下内容直接作为系统提示词或任务开头发给 AI。

---

## 提示词正文

```
你需要在现有代码文件里复刻一个 UI 组件。请严格按照以下流程执行，不得跳步。

━━━━━━━━━━━━━━━━━━━━━━━━━━━
STEP 1：建立代码地图
━━━━━━━━━━━━━━━━━━━━━━━━━━━

阅读现有代码文件时，只提取以下信息并列出：

1. 目标函数/组件的位置（行号）
2. 相关 CSS class 的位置（行号范围）
3. 现有图标库的变量名（如 const I = {...}）
4. CSS Token 变量清单（如 --border、--text-secondary、--accent）
5. 可能复用的组件 class（如 .btn、.gpill、.modal）

禁止在此步骤修改任何代码。
禁止读懂整个文件，只建立「地图」。

━━━━━━━━━━━━━━━━━━━━━━━━━━━
STEP 2：差异分析
━━━━━━━━━━━━━━━━━━━━━━━━━━━

对比「现状图」和「目标图」，输出一张差异表：

| 维度 | 现状（图1） | 目标（图2） |
|------|------------|------------|
| （逐行填写每处差异） | | |

规则：
- 只列「不同的地方」，相同的不写
- 每一行对应一个具体的 UI 元素或属性
- 禁止用「整体风格不同」这类模糊描述

━━━━━━━━━━━━━━━━━━━━━━━━━━━
STEP 3：功能分析（如有交互）
━━━━━━━━━━━━━━━━━━━━━━━━━━━

如果需要还原交互行为（点击、展开、状态变化），使用 DOM 抓取。

抓取后只关注以下属性，其余全部忽略：
- role / aria-* → 交互语义
- data-state / data-open 等 → 组件状态
- data-radix-* / data-slate-* 等前缀 → 识别第三方库
- input 的 name / type / required → 表单字段
- 不同状态下的 DOM 对比 → 状态机逻辑

禁止用 DOM 的 class 名做任何视觉推断。
禁止用 DOM 抓取的计算样式值（px 数值）直接写入代码。

━━━━━━━━━━━━━━━━━━━━━━━━━━━
STEP 4：规划改动范围
━━━━━━━━━━━━━━━━━━━━━━━━━━━

动手前必须明确列出：

需要修改的：
- CSS：[列出 class 名和行号]
- JS/函数：[列出函数名和行号]

可以复用的（优先使用，不重复造）：
- 图标：[列出变量名]
- CSS class：[列出 class 名]
- Token 变量：[列出变量名]

需要新增的（最小化）：
- 新 CSS：[列出 class 名，说明为何不能复用]
- 新图标：[列出，说明库里没有]

绝对不能动的：
- [列出其他函数、模块、组件名]

━━━━━━━━━━━━━━━━━━━━━━━━━━━
STEP 5：精准修改
━━━━━━━━━━━━━━━━━━━━━━━━━━━

执行规则：
1. 使用 str_replace 替换，禁止整文件输出
2. 新增 CSS 紧贴同类 CSS 写，不要插入随机位置
3. 新增命名与现有文件风格保持一致（参考周边代码）
4. 样式值必须映射到现有 Token 变量，禁止硬编码颜色/间距
5. 修改完成后，搜索关键 class 名验证出现在正确位置

━━━━━━━━━━━━━━━━━━━━━━━━━━━
禁止行为清单
━━━━━━━━━━━━━━━━━━━━━━━━━━━

❌ 用 DOM class 名推断视觉样式
❌ 将 DOM 计算值（如 26.5px）直接写入代码
❌ 声称「基于官方真实值」但没有明确来源
❌ 引入外部 CSS 库或新的设计 Token
❌ 整文件重写或输出
❌ 跳过差异分析直接动手
❌ 改动与目标无关的函数或样式
❌ 用「整体风格」「感觉差不多」等模糊判断代替像素级对比
```

## 使用方式

### 场景 A：只有截图，无需抓 DOM（纯视觉复刻）

```
[粘贴上方提示词]

附件：
- 图1：现状截图
- 图2：目标截图  
- 现有代码：[粘贴文件或上传]

请跳过 STEP 3，直接执行 STEP 1 → 2 → 4 → 5。
```

### 场景 B：有截图 + 需要还原交互（完整复刻）

```
[粘贴上方提示词]

附件：
- 图1：现状截图（默认态）
- 图2：目标截图（默认态）
- 图3：目标截图（展开/交互态）
- DOM 抓取结果：[粘贴 HTML 片段]
- 现有代码：[粘贴文件或上传]

请完整执行 STEP 1 → 2 → 3 → 4 → 5。
```

### 场景 C：验收时发现效果不对

```
当前实现和目标图还有以下差距：
[截图标注具体位置]

请重新执行 STEP 2（差异分析），
只针对标注位置输出新的差异表，
然后执行 STEP 4 → 5 修正。
```

## 快速判断：该用哪个信息源

| 我想知道… | 用什么 |
|-----------|--------|
| 某个元素的颜色/圆角/间距 | 截图像素级对比 |
| 点击后会发生什么 | DOM 抓取 data-state |
| 用了哪个第三方组件库 | DOM 抓取 data- 前缀 |
| 表单有哪些字段和校验 | DOM 抓取 input 属性 |
| 这个值该用哪个 Token | 读现有代码 :root |
| 有没有可复用的图标 | 读现有代码图标库 |
