# AI 处理老旧代码的系统方法论

改造一个 3000 行的老旧 HTML 文件时，如果让 AI 从头读到尾再动手，结果往往是改一处坏一处。下面这套四步法，专门用于系统性地处理这类任务。

---

## 第一步：建立代码地图（读懂架构，而非内容）

拿到一个大型文件，不要从头到尾读，而是做**定向扫描**，只找几个关键问题的答案：

- **弹窗/组件是怎么触发的？** → 找到对应的函数入口
- **HTML 结构在哪里？** → 找到对应的 DOM 容器
- **样式系统是什么？** → 发现 `:root` 里的 CSS Token 体系
- **已有哪些可复用的图标和组件？** → 找到图标库和已有 class

**核心原则：先建立「地图」，再动手改代码。**

---

## 第二步：差异分析（对比两张图，做 delta 分析）

不是描述目标图长什么样，而是精准列出**现状图和目标图之间的差异**：

| 维度 | 现状 | 目标 |
|------|------|------|
| 顶部右侧 | 按钮 + 关闭图标 | 只有关闭图标 |
| Pills 数量 | 4 个，无边框 | 8 个，有描边胶囊 |
| 描述区 | 静态 `<div>` | 可输入的 `<textarea>` |
| 关键区域 | 普通文字行，居上 | 带边框卡片，居底 |
| 整体布局 | 固定高度 | flex 纵向，描述区撑满中间 |

**核心原则：差异分析比全量描述更精准，能避免「改对了目标，改坏了其他」。**

---

## 第三步：在现有系统内解决（复用 > 新增）

发现项目已有：

- 图标库中的既有图标 → 直接复用
- 现有的 class（如 `.gpill`、`.btn`、`--border` 等） → 直接复用
- 现有的弹窗样式（如 `.modal.wide`） → 作为基础修改而非重写

缺少的（如特定图标、特定样式类）才新增，且命名风格与文件保持一致。

**核心原则：能复用的绝不新写，新写的要跟原有风格对齐。**

---

## 第四步：精准手术（最小改动范围）

把整个改动集中在**最少的几处**：

1. 目标组件的 CSS（原 3 行 → 新 6 行）
2. 相关元素（如 pills）的 CSS（原 4 行 → 新 12 行）
3. 核心函数体（原 1 个函数 → 重写 1 个函数）

完全没有动侧边栏、路由、图标库、其他弹窗等任何无关代码。

**核心原则：最小改动范围，最大还原效果。手术刀，不是铲车。**

---

## 附录：给 AI 的 Prompt 模板

```
你需要在现有 HTML 文件里修改一个弹窗组件，复刻目标图的效果。

## 处理步骤（必须按顺序）

### Step 1：建立代码地图
在读文件时，只需要找到以下信息并记录：
- 目标函数在哪一行
- 弹窗相关的 CSS class 在哪一行（搜索 .modal、.gpill 等）
- 现有图标库变量名
- 现有 CSS Token 变量名（如 --border、--text-secondary）
- 不需要读懂整个文件，只需要建立「地图」

### Step 2：差异分析
对比两张图，列出一张明确的差异表：
- 哪些元素「新增」了
- 哪些元素「删除」了
- 哪些元素「样式变了」但结构没变
- 哪些是「布局/间距」的变化

### Step 3：规划改动范围
在动手前，明确说出：
- 需要改哪些 CSS 规则（行号范围）
- 需要改哪个 JS 函数（函数名）
- 哪些图标/class 可以复用（列出名称）
- 哪些需要新增（列出新增内容）
- 哪些绝对不能动（其他弹窗、路由、侧边栏等）

### Step 4：精准修改
- 用 str_replace 替换，不要整文件输出
- 新增 CSS 紧贴原有同类 CSS 写，命名风格保持一致
- 新增图标 SVG 内联在函数里，不污染全局图标库
- 改完后验证：搜索关键 class 名，确认出现在正确位置

## 约束
- 不引入任何外部库
- 不改变文件的模块结构
- 新 CSS 类名的命名规范与现有文件保持一致
- 遇到「现有图标库里有类似图标」优先复用，不要重复造轮子
```
